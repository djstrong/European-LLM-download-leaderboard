# Development / pipeline notes

The public leaderboard lives in [`README.md`](README.md) (regenerated by CI). This file documents how the pipeline works and how to add models.

Track **last-30-day Hugging Face downloads** for European LLMs, aggregating official format variants (GGUF, MLX, FP8, …) under regex-defined leaderboard rows. Also records **parameter counts** and an append-only history of snapshots.

## Config (single source of truth)

Edit [`european-llm-hf-download-leaderboard.json`](european-llm-hf-download-leaderboard.json):

| Change | How |
|--------|-----|
| New model / row | Add `models.{row_id}` with `display_name`, `official_org`, `regex[]`, metadata |
| New regex / variants | Edit that row’s `regex` list |
| New org | Set `official_org` on a row (scanned automatically) |
| Prefetch org without rows | Optional top-level `"organizations": ["org-name"]` (union with per-row orgs) |
| Retire a row | Remove it or set `"active": false` |
| Display rename | Change `display_name` only — keep `row_id` stable for history |

**Stable `row_id` keys** (`bielik-11b-v3.0`, `gams3-12b`, …) are the primary key in the manifest, snapshots, and timeseries. Do not rename them if you want continuous charts.

Scripts never hardcode org names or regexes. Validate without Hub calls:

```bash
python scripts/resolve_model_repos.py --validate-config
```

Deduplication: each Hugging Face repo id is assigned to the **first** matching row in JSON key order. Put narrower patterns before broader ones.

## Pipeline (two scripts)

```text
config JSON ──► resolve_model_repos.py ──► data/manifest/latest.json
                                              │
                                              ▼
                     fetch_download_stats.py ──► data/metrics/snapshots/YYYY-MM-DD.json
                                              ├──► data/metrics/timeseries.jsonl
                                              └──► output/leaderboard.json + .csv
                                                         │
                     render_leaderboard_md.py ◄──────────┘
                                              └──► README.md  (also optional output/leaderboard.md)
```

### 1. Resolve repos (org list + regex)

```bash
pip install -r requirements.txt

python scripts/resolve_model_repos.py \
  --config european-llm-hf-download-leaderboard.json \
  --out data/manifest/latest.json \
  --audit \
  --diff
```

- Lists all models under each `official_org` (and optional `organizations`) via the Hub API.
- Matches repo ids with Python regexes (`re.match` on the full id).
- Writes the manifest; archives the previous file under `data/manifest/history/` when `manifest_content_hash` changes.
- Does **not** fetch download counters.

### 2. Fetch stats (downloads + parameters)

```bash
python scripts/fetch_download_stats.py \
  --manifest data/manifest/latest.json \
  --metrics-dir data/metrics \
  --output-dir output \
  --concurrency 8 \
  --max-retries 3
```

Per repo (in parallel):

`GET /api/models/{id}?expand[]=downloads&expand[]=downloadsAllTime&expand[]=safetensors&expand[]=gguf`

| Field | Meaning |
|-------|---------|
| `downloads` | Rolling **last 30 days** |
| `downloadsAllTime` | Lifetime total |
| `safetensors.total` / `gguf.total` | Parameter count |

Row totals **sum** downloads across member repos. Row **parameters** take the **max** non-null count among members (not a sum). Incomplete rows (failed member fetches) set `complete: false`.

Useful flags:

| Flag | Default | Purpose |
|------|---------|---------|
| `--concurrency` | `8` | Parallel Hub requests |
| `--max-retries` | `3` | Retries after first failure (backoff + jitter; honors `Retry-After`) |
| `--allow-partial` | off | Write outputs and exit 0 even if some repos fail |
| `--token` / `HF_TOKEN` | unset | Recommended to reduce 429s |
| `--momentum-smoothing` | `100000` | Smoothing constant `C` in the momentum formula below |

### Momentum metric

Each row (and each organization rollup) gets a `momentum_score`:

```text
momentum = downloads_30d / (downloads_all_time + C)   # C = --momentum-smoothing, default 100,000
```

A raw `downloads_30d / downloads_all_time` ratio lets a brand-new repo with a
handful of total downloads look like it has near-100%/"infinite" momentum,
which is just sample-size noise, not real signal. Adding a smoothing constant
`C` to the denominator means a row needs a meaningful download volume before
the ratio can get large, so a high momentum score reflects sustained recent
pull relative to genuine lifetime traffic — not a fluke from a tiny sample.
Both `rank` (by `total_downloads_30d`) and `momentum_rank` (by
`momentum_score`) are included per row/org so you can sort either way.

### Org rollup fields

Each entry in `leaderboard_orgs.json` covers one `official_org` and includes:

- `total_downloads_30d` / `total_downloads_all_time` / `momentum_score` — **summed** across every model version the org publishes, with `rank` / `momentum_rank` for that sum.
- `top_model_row_id` / `top_model_display_name` / `top_model_downloads_30d` / `top_model_downloads_all_time` / `top_model_overall_rank` — the org's single **best individual model** (no summing), i.e. their biggest hit, plus that model's rank in the main per-model leaderboard. `rank_by_top_model` ranks orgs against each other on this metric.

## Storage layout

```text
data/
  manifest/
    latest.json                 # repo ↔ row mapping
    history/*.json              # prior manifests when mapping changes
  metrics/
    snapshots/YYYY-MM-DD.json   # per-repo + per-row point-in-time
    timeseries.jsonl            # one compact line per fetch run
output/
  leaderboard.json              # ranked current view, per model row (incl. momentum_score)
  leaderboard.csv
  leaderboard_orgs.json         # same downloads rolled up per official_org (incl. momentum_score)
  leaderboard_orgs.csv
README.md                       # Markdown leaderboard (CI + render_leaderboard_md.py)
```

### 3. Render Markdown (repo README)

```bash
python scripts/render_leaderboard_md.py \
  --input output/leaderboard.json \
  --orgs-input output/leaderboard_orgs.json \
  --output README.md
```

Adds a "Momentum" column to the per-model table plus an "Organizations"
section (org-level totals + a "Top by momentum" table). The org section is
skipped automatically if `--orgs-input` is missing. Optional: `--limit 50`
for a shorter model table. CI runs this in `.github/workflows/fetch.yml` and
commits `README.md`.

### Historical data caveat

The Hub API does **not** expose past calendar months — only the **current** rolling 30-day window and all-time total. History here is what **you** record over time by committing daily snapshots and `timeseries.jsonl`. Day-over-day deltas of `downloads_all_time` approximate new activity; they are not identical to “downloads last month.”

## GitHub Actions

Independent workflows (fetch does **not** wait for resolve):

| Workflow | Triggers | Commits |
|----------|----------|---------|
| [`.github/workflows/resolve.yml`](.github/workflows/resolve.yml) | Push to config / resolve script, weekly cron, manual | `data/manifest/` |
| [`.github/workflows/fetch.yml`](.github/workflows/fetch.yml) | Daily cron, manual | `data/metrics/`, `output/`, `README.md` |

Optional repository secret: `HF_TOKEN` (public models work without it; token reduces rate limits).

After editing the config, merge the change so **resolve** runs on push before the next daily **fetch**, or trigger resolve via `workflow_dispatch`.

## Local quickstart

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

python scripts/resolve_model_repos.py --audit --diff
python scripts/fetch_download_stats.py --concurrency 8 --allow-partial
python scripts/render_leaderboard_md.py   # writes README.md
```

Inspect `README.md`, `output/leaderboard.json`/`.csv`, or
`output/leaderboard_orgs.json`/`.csv`.
